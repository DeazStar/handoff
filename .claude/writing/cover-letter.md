# Writing the cover letter

Read this before you call `save_cover_letter`. You write only the body paragraphs. The server adds the sender block (name, city, email), the date, the recipient, the greeting ("Dear Hiring Manager," or the contact's first name) and the sign-off, and draws a one-page PDF. Facts only: every claim cites the facts it rests on, and a number must appear in them.

## The shape: 3 to 4 short paragraphs, 180 to 300 words
1. **Opening (about 50 to 70 words).** Starts "I'm applying for the <role> at <company>." Then one sentence on who the user is (the kind of engineer, the years, the stack that matches), and, if it is true and specific, one sentence on the part of the company's stack the user has used.
2. **The strongest experience (75 to 100 words).** One employer, one clear thing done, in plain words, with what it covers. This is the heart of the letter.
3. **A second experience (50 to 90 words).** A different employer. If it carries a real number from a fact, use it. A real, honest tie to the job is welcome ("so mobile work is familiar to me"), a forced one is not. This paragraph is optional; skip it and write a shorter letter rather than pad.
4. **Close (about 15 to 30 words).** "Happy to talk if it looks like a fit. Thank you for your time and consideration." If the user needs visa sponsorship and the form and profile do not already say so, one plain sentence before the thanks ("I'd need visa sponsorship.").

## Rules
- **Name the role once, in the first sentence.** After that, talk about what the user did. Never open a paragraph by repeating the posting ("The posting asks...", "The role covers...", "You are building...", "Your posting describes..."). The match shows in what the user did.
- **Each employer appears once**, in one paragraph. Use two or three employers at most, not a tour of every job.
- **Never force a match.** Connect a posting need to a fact only when the fact says nearly the same thing. If it does not, leave the need out.
- **Never mention a requirement the user lacks** (the posting's Go backend, AWS...). Name only the parts of the stack the user matches.
- **Do not talk about the posting's wish list.** Not "mobile experience is a bonus for you". Write "I've also built a mobile app in Node.js and Flutter" if it is true.
- **At most two numbers** in the whole letter, besides the years ("3+ years"), and each from a fact. A letter is not a list of results.
- **No claimed feelings** ("passionate", "eager", "excited", "huge passion", "drawn to"), no "I am writing to express my interest", no "I look forward to hearing from you".
- **Short sentences**, under 30 words, one idea each. No dashes joining clauses.

## Good example (Globex, the user's facts; 194 words)
> I'm applying for the Software Engineer role at Globex. I'm a software engineer with 3+ years building backend APIs and web products in TypeScript, Node.js, React and PostgreSQL. Your web app is built in React and TypeScript, which I used to build a full-stack e-commerce platform at Fabrikam. There I also optimized server logic and database interactions and improved UI performance by 20%.
>
> I lead backend work at Northwind, a payments platform that connects merchants with banks across Kenya. I design its REST APIs and authentication for sensitive payment data, own the database schema and performance, and manage the CI/CD and Docker deployments that keep the system reliable for a growing user base.
>
> At Contoso I developed the backend APIs for data ingestion and for integration with reporting pipelines, and cut query time by more than 60 percent. I also put input validation and access control in place across the services. As a freelancer I built a mobile and web app in Node.js and Flutter for a city council, so mobile work is familiar to me.
>
> Happy to talk if it looks like a fit. Thank you for your time and consideration.

## Bad example, and what is wrong in it
> I'm applying for the Software Engineer role at Globex. **You are building a tool for teams to track and automate their mobile app releases, with a Go backend and a React and TypeScript web app.** *(repeats the posting, and points at the Go gap)* At Fabrikam I built a full-stack e-commerce platform... At Northwind I lead backend work...
>
> **The role covers release automation and third-party integrations.** *(repeats the posting)* **At Northwind I manage the deployment workflows with CI/CD and Docker...** *(Northwind again; a forced match: managing deployments is not building release automation)*
>
> **Mobile experience is a bonus for you.** *(talks about the wish list)* I built a mobile and web application... 99.99% accuracy *(a number with no context)*.
>
> **The posting describes a distributed team where early engineers make technical decisions across the stack.** *(repeats the posting again; says nothing about the user)* Happy to talk if it looks like a fit.

## The hard rules the server enforces
- 3 to 4 paragraphs, 180 to 300 words, one page.
- Paragraph 1 starts "I'm applying for the... at...".
- No paragraph that opens by repeating the posting; no "is a bonus/plus" talk.
- Each employer named in only one paragraph.
- At most two numbers besides the years, each in the cited facts.
- No filler, stock lines or sentences over 35 words (the general writing rules also apply).

## Before you save
Check: each employer once; no sentence starts from the posting; no requirement the user lacks is named; the first sentence names the role and company; no claimed feeling; read it aloud.
